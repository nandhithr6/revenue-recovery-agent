# Sources and honesty statement

## The data in this project is synthetic

No real payment data is used anywhere in this repository. Every transaction,
customer and outcome is generated by the simulator in `src/sim/`.

We do this deliberately and say so plainly, because real failed-payment data is
merchant-confidential. What we *can* do honestly is ground the simulation in
publicly documented behaviour, and be explicit about the line between the two.

## What is real

The failure `reason` codes in `src/domain/failure-taxonomy.ts` are Razorpay's own
documented payment error reasons, taken from their public error documentation:

- Card error codes — <https://razorpay.com/docs/errors/payments/cards/>
- UPI error codes — <https://razorpay.com/docs/errors/payments/upi/>
- Error structure (`code`, `description`, `source`, `step`, `reason`, `metadata`)
  — <https://razorpay.com/docs/errors/>

Using the real vocabulary means this system speaks the same language as a live
Razorpay integration: the taxonomy would not need rewriting to point it at a
production webhook feed.

## What is our own modelling

These are assumptions we made. They are reasoned, not measured:

1. **The `RecoveryClass` assigned to each reason.** Razorpay documents what each
   error means and suggests next steps; grouping those into six recovery classes
   is our contribution.
2. **Recovery probability curves** — how likely a retry is to succeed, as a
   function of recovery class and elapsed time. Documented in
   `src/sim/recovery-model.ts`.
3. **Cost model** — per-attempt gateway cost and per-contact goodwill cost.
4. **Failure mix** — the relative frequency of each reason in a cohort.

Every one of these is a named, tunable constant with a comment explaining the
reasoning. None is presented as an empirical finding.

## How to read the results

The headline numbers compare strategies **against each other on identical
simulated cohorts with a fixed random seed**. That is a fair comparison of
*policy quality*, which is what this project is about.

It is not a prediction of rupees recoverable in production. Anyone claiming that
from synthetic data would be overselling, and we are not going to.
